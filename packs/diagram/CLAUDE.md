You are producing a narrated Hyperframes demo reel in the exact style of the
OpsRamp on-prem architecture journey reel (2026-09, HPE Chief Technologist
council). This file is your standing orders. The subject changes; the craft,
brand, pipeline, and governance do not.

Read these companions in this directory before writing anything:

- `STYLE_FRAME.md` — the visual system: colors, HPE Graphik, spacing, the
  frame anatomy, component idioms.
- `NARRATION_GUIDE.md` — voice, tone, sentence shapes, timing math.
- `CUTS_AND_MOTION.md` — cut grammar, transitions, cue/beat choreography.
- `PROCESS.md` — the phase pipeline, commands, review gates, governance.
- `templates/` — fill-in skeletons for BRIEF, SCREENPLAY, and scenes.mjs.

## The one architectural fact that matters

**`scenes.mjs` is the single source of truth.** Narration text (`vo`), scene
titles, diagram geometry, and word-cued reveals all live there. STORYBOARD.md
and `compositions/*.html` are GENERATED by `npm run build` — never edit them
by hand. Narration audio and word timings come from `npm run narrate` (Edge
TTS with WordBoundary metadata); diagram items appear when the narrator says
their cue phrase. Change the words and the choreography follows.

## Setup (once)

1. Copy the machinery from the reference reel — not the subject:
   ```bash
   SRC=demo/opsramp-onprem-architecture-reel   # in the hyperframes-reel repo
   mkdir <your-reel> && cd <your-reel>
   cp -R $SRC/scripts $SRC/tests $SRC/assets $SRC/package.json \
         $SRC/package-lock.json $SRC/hyperframes.json $SRC/index.html .
   rm -rf assets/audio/* assets/reference/*   # subject-specific; yours will regenerate
   npm ci && npm run doctor
   ```
   Keep `assets/*.css` (rename/adjust tokens only per STYLE_FRAME.md). The
   HPE Graphik OTFs ship in THIS pack — copy `assets/fonts/` from the pack
   into your reel's `assets/fonts/` (see STYLE_FRAME.md for provenance and
   the license note).
2. Pins are part of the style: `hyperframes@0.8.62`, registry
   `1b8f8a43d43bc2456075215b066b23e11d821435` (in `hyperframes.json`). Do not
   upgrade mid-production.
3. Set `HYPERFRAMES_NO_TELEMETRY=1` on every Hyperframes command. Never use
   `publish` or hosted/cloud rendering for internal material.

## Production phases (each ends at a human gate — do not skip ahead)

1. **BRIEF** (`templates/BRIEF.template.md` → `BRIEF.md`). One message
   sentence, the audience, the worry the reel answers, and the claims SOURCE
   (a named owner). GATE: owner approves the message and arc.
2. **SCREENPLAY** (`templates/SCREENPLAY.template.md` → `SCREENPLAY.md`).
   Every line: Visual + Claims + the narration paragraph. Mark unconfirmed
   claims **CHECK**. GATE: owner reads every word aloud-able line; all CHECKs
   resolved before recording.
3. **SCENES** (`templates/scenes.skeleton.mjs` → `scenes.mjs`). Transcribe
   narration verbatim into `vo`; lay out diagrams on the 1744×632 stage; cue
   every reveal to a phrase from that scene's own narration.
4. **NARRATE + BUILD**: `npm run narrate` then `npm run build`. Read the
   generated durations back into your head — a scene under 8s or a cue that
   never fires is a story bug, not a tooling bug.
5. **CHECK + PREVIEW**: `npm run check` (lint, runtime, layout, motion,
   contrast — all must pass), then
   `HYPERFRAMES_NO_TELEMETRY=1 npx hyperframes preview --background --port 3017`
   and open http://localhost:3017/ for the owner's Studio review. GATE: owner
   signs off the cut in Studio. Stop the preview afterward (`preview --stop`).
6. **RENDER + VERIFY**: `npm run render` (base MP4 → captions + chapters via
   finish) then `npm run verify`. Deliverable is the finished MP4 plus the
   verification report.

## Story rules this style is known for (non-negotiable)

- **Open on the audience's worry, phrased as a question. Answer it in the
  first ten seconds. Spend the reel proving the answer. Close by returning to
  the question verbatim.** (Frame 1 "Are we building a second platform?" →
  Frame 20 answers it.)
- **One dominant idea per frame.** If a frame needs two sentences of support
  copy, it is two frames.
- **A recurring anchor object.** Introduce one visual (the on-prem reel used
  the five-socket contract band) in the first act, then bring it back in
  every act — "watch this band" is what makes 13 minutes feel like one
  argument.
- **Part recaps and a closing ledger.** End each act with a recap frame; end
  the reel with a single frame that shows the whole argument at once.
- **Claims come from the named owner only.** Slide decks and reference
  material supply terminology, never claims, order, or conclusions. No
  fabricated telemetry, customers, or status. Label anything a viewer could
  misread with a small factual source/status line.

## Working with the user

Ask one question at a time. Present the screenplay in per-act sections for
approval, not as one dump. Give a cost/length estimate before narrating or
rendering. When the owner corrects a claim, fix SCREENPLAY.md and scenes.mjs
in the same edit — they must never drift apart.
